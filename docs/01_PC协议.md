# 01 PC 端串口协议（M1 测试治具）

> 帧格式与状态码沿用 `IINFO/M1 测试治具PC端通讯协议.xlsx`；
> 命令码按 M1 的实际功能新定（编号风格与 R1 治具一致）。

## 1. 物理层

| 项 | 值 |
|---|---|
| 接口 | U1：H1 的 1/3 脚（U1-RX1 / U1-TX1）；U2：H3 的 1/3 脚 |
| 电平 | 3.3V TTL，交叉接 USB-TTL |
| 波特率 | **460800**，8N1，无流控 |
| 字节序 | 所有多字节字段**大端**（高字节在前） |

## 2. 帧格式

```
A5 5B | CMD(2) | SEQ(2) | LEN(2) | DATA(L) | CRC16(2)
```

- `CMD`：命令码，2 字节
- `SEQ`：PC 从 0x0001 递增，到 0xFFFF 回 1；治具 ACK 原样回填；治具主动上报固定 0
- `LEN`：DATA 字节数
- `CRC16`：MODBUS（多项式 0xA001 反射，初值 0xFFFF），范围 = 帧头到 DATA 末尾，**高字节在前**
- 最短帧 10 字节（LEN=0）

行为约定：

| 情况 | 治具行为 |
|---|---|
| 正常帧 | 回 1 个 ACK（CMD 与 SEQ 原样回填） |
| CRC 错 | **不回 ACK**（只内部计数，可用 0x0030 查） |
| 未知命令 | 回 ACK，DATA = `FF`（NIY） |
| 运动中收到 MOVE | 回 `01`（BUSY） |
| 运动中收到 TMC_QUERY / TMC_SET_IRUN | 回 `01`（BUSY），避免位操作挤占 STEP 中断 |

## 3. 状态码（与协议表一致）

| 值 | 名称 | 说明 |
|---|---|---|
| 0x00 | OK | 成功 |
| 0x01 | BUSY | 忙 |
| 0x02 | ERR_SIZE | 长度/大小异常 |
| 0x03 | ERR_FLASH | Flash 读写失败 |
| 0x04 | ERR_PROG | 烧录失败 |
| 0x05 | ERR_TEST | 测试不合格 |
| 0x06 | ERR_NO_FW | 固件不存在 |
| 0x07 | ERR_INCOMPLETE | 固件不完整 |
| 0x08 | ERR_CRC | 帧 CRC 错（不回 ACK） |
| 0x09 | ERR_SEQ | 序号非递增（仅告警） |
| 0x0A | ERR_COUNT | 字节数不符 |
| 0x0B | ERR_PARAM | 参数错误 |
| 0x0C | ERR_TIMEOUT | 超时 |
| 0x0D | ERR_OVERFLOW | 溢出 |
| 0xFF | NIY | 未实现 |

> **ACK 的 DATA[0] 永远是状态码。**

## 4. 命令表

| 命令 | 值 | 适用 | PC 下发 | 治具应答 |
|---|---|---|---|---|
| PING | 0x0001 | U1/U2 | 无 | `状态(1)` |
| GET_VERSION | 0x0002 | U1/U2 | 无 | `状态 + 主 + 次 + 修订`（4B） |
| GET_UID | 0x0003 | U1/U2 | 无 | `状态 + 96bit UID`（13B） |
| MEASURE_ADC | 0x000E | U1/U2 | `mode(1)` | `状态 + ADC 快照`（51B） |
| SENSOR_READ | 0x000F | U1/U2 | `mode(1)` | `状态 + 对射结果`（20B） |
| MOTOR_MOVE | 0x0010 | U2 | `dir(1)+steps(4)+freq(2)` | `状态(1)` |
| MOTOR_STOP | 0x0011 | U2 | 无 | `状态(1)` |
| MOTOR_STATUS | 0x0012 | U2 | 无 | `状态+busy+done+target`（10B） |
| TMC_QUERY | 0x0020 | U2 | 无 | `状态+TMC 快照`（17B） |
| SENSOR_CONFIG | 0x0021 | U1/U2 | `ch(1)+block(2)+release(2)` | `状态(1)` |
| TMC_SET_IRUN | 0x0022 | U2 | `irun(1)+ihold(1)` | `状态(1)` |
| SELF_TEST | 0x0030 | U1/U2 | 无 | `状态 + 自检位图`（6B） |

U1 收到 0x0010/0x0011/0x0012/0x0020/0x0022 会回 `FF`（它没有电机硬件）。

### 4.1 MEASURE_ADC（0x000E）

- `mode=0`：直接返回后台最近一轮快照（不触发新采集）
- `mode=1`：立即采一轮 8 路（约 1.5ms）后返回
- 其他值 → `0x0B`

应答 DATA（51 字节）：

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 1 | 状态码 | 0x00 |
| 1 | 1 | flags | bit0=快照有效，bit2=VDDA 已校准 |
| 2 | 1 | 通道数 | 固定 8 |
| 3 | 2 | round | 回合号，每刷新一次 +1 |
| 5 | 2 | interval_ms | 本轮 8 路采集耗时 |
| 7 | 2 | vdda_mv | 校准后的 VDDA（mV） |
| 9 | 2 | 配置指纹 | 0x05（239.5 周期）<<8 \| 平均次数 |
| 11 | 8×5 | 通道数据 | 见下 |

每通道 5 字节（顺序固定 ADC0..ADC7）：

| 偏移 | 长度 | 字段 |
|---|---|---|
| 0 | 2 | raw（12bit 原始值） |
| 2 | 2 | mv（**输入侧**电压，ADC2 已按 ÷0.4 还原） |
| 4 | 1 | flags：bit0=有效，bit1=贴边（≤4 或 ≥4091），bit2=对射通道 |

通道功能见 `00_硬件与引脚.md` 第 2 节。

### 4.2 SENSOR_READ（0x000F）

- `mode=0`：返回最近状态；`mode=1`：立即采一次
- 应答 DATA（20 字节）：

| 偏移 | 长度 | 字段 |
|---|---|---|
| 0 | 1 | 状态码 |
| 1 | 1 | flags：bit0=两路都有效，bit1=通道1 遮挡，bit2=通道2 遮挡 |
| 2 | 9 | 通道1：raw(2)、mv(2)、block_mv(2)、release_mv(2)、blocked(1) |
| 11 | 9 | 通道2：同上 |

### 4.3 SENSOR_CONFIG（0x0021）

下发 5 字节：`ch(1) + block_mv(2) + release_mv(2)`，要求：

- `ch < 2`
- `release_mv < block_mv`（回差必须为正）
- `block_mv ≤ 3300`

不满足 → `0x0B`，参数保持原值。

### 4.4 MOTOR_MOVE（0x0010，仅 U2）

下发 7 字节：

| 偏移 | 长度 | 字段 | 取值 |
|---|---|---|---|
| 0 | 1 | dir | 0=CW，1=CCW |
| 1 | 4 | steps | 1 ~ 100000000（16 微步：3200 步/圈） |
| 5 | 2 | freq_hz | 500 ~ 20000（超出返回 0x0B） |

非阻塞：立即回 ACK，用 0x0012 查进度；运动中再发 → `0x01`。
到位后 EN 保持使能（IHOLD 保持力矩）；`MOTOR_STOP` 会停脉冲并脱机。

`MOTOR_STATUS` 应答 10 字节：`状态 + busy(1) + done(4) + target(4)`。

### 4.5 TMC_QUERY（0x0020，仅 U2）

应答 17 字节：

| 偏移 | 长度 | 字段 |
|---|---|---|
| 0 | 1 | 状态码 |
| 1 | 1 | alive（1=通信成功） |
| 2 | 1 | cfg_ok（1=关键寄存器读回校验通过） |
| 3 | 4 | GCONF |
| 7 | 4 | CHOPCONF |
| 11 | 4 | DRV_STATUS |
| 15 | 2 | SG_RESULT（低 10 位） |

通信失败时寄存器字段为 0，`alive=0`。

### 4.6 SELF_TEST（0x0030）

应答 6 字节：`状态 + mask(1) + vdda(2) + rail_mask(1) + crc_err_cnt(1)`

mask 位定义：

| 位 | 含义 |
|---|---|
| 0 | 8 路 ADC 全部采集成功 |
| 1 | 对射通道1 采集成功 |
| 2 | 对射通道2 采集成功 |
| 3 | VDDA 在 3000~3600mV |
| 4 | TMC2209 通信且配置校验通过（U1 恒 0，不参与判定） |
| 5 | 电机空闲（U1 恒 1） |
| 6 | 串口 FIFO 无溢出 |
| 7 | 无帧 CRC 错误（不参与判定） |

`状态 = 0x00` 当且仅当 mask 的低 7 位全为 1，否则 `0x05`（ERR_TEST）。
`rail_mask` 表示哪些通道贴边（bit0=ADC0 …）。

## 6. 与 IINFO 协议表的差异

- **相同**：帧结构、大端、CRC16-MODBUS、状态码、SEQ 规则、460800。
- **不同**：命令码。协议表里的固件上传（0x0009/0x000A/0x000B）、烧录（0x0112）、
  版本查询（0x000C/0x000D）是 FOC 治具的 OTA/ISP 功能，M1 板没有 SPI Flash，
  这些命令一律回 `FF`（NIY）。M1 的 0x000E/0x000F 沿用协议表编号，但数据内容按本板功能重定义。
