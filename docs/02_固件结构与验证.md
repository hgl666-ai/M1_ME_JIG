# 02 固件结构、验证与上板首测

## 1. 工程结构

两颗 MCU 各一个 Keil 工程，**共享模块逐字节一致**（改一处就同步复制到另一边）：

```
U1/  (BOARD_U1)                         U2/  (BOARD_U2)
├─ Core/Inc/                            ├─ Core/Inc/
│   ├─ app_config.h      ← 共享         │   ├─ (同上，逐字节一致)
│   ├─ app.h             ← 共享         │   ├─ bsp_motor.h        ← 仅 U2
│   ├─ bsp_adc.h         ← 共享         │   └─ bsp_tmc2209.h      ← 仅 U2
│   ├─ bsp_clock.h       ← 共享         │
│   ├─ bsp_sensor.h      ← 共享         │
│   ├─ bsp_uart.h        ← 共享         │
│   ├─ protocol.h        ← 共享         │
│   └─ protocol_frame.h  ← 共享         │
└─ Core/Src/                            └─ Core/Src/
    ├─ app.c             ← 共享             ├─ (同上)
    ├─ bsp_adc.c         ← 共享             ├─ bsp_motor.c         ← 仅 U2
    ├─ bsp_clock.c       ← 共享             └─ bsp_tmc2209.c       ← 仅 U2
    ├─ bsp_sensor.c      ← 共享
    ├─ bsp_uart.c        ← 共享
    ├─ protocol.c        ← 共享（U2 独有命令用 #if defined(BOARD_U2) 包住）
    └─ protocol_frame.c  ← 共享
```

Keil 里新增的分组是 `Application/User/BSP`，编译宏分别是 `BOARD_U1` / `BOARD_U2`
（与 `USE_HAL_DRIVER,STM32F103x6` 并列）。

| 模块 | 职责 |
|---|---|
| `bsp_clock.c` | 兜底把时钟切到 HSE 8MHz×8=64MHz（晶振不起振则保留 HSI，不阻塞启动） |
| `bsp_uart.c` | USART1 115200 8N1；**DMA1_Channel5 循环接收** + 768B FIFO（长耗时命令期间也不丢字节） |
| `bsp_adc.c` | 8 路轮询采集、VREFINT 反算 VDDA、分压还原、贴边检测 |
| `bsp_sensor.c` | 对射判定：阈值 + 回差 + 连续 3 次去抖 |
| `protocol_frame.c` | 组帧/解帧 + CRC16-MODBUS |
| `protocol.c` | 收帧状态机（逐字节）+ 命令分发 + ACK |
| `app.c` | 后台 ADC 快照（200ms）、对射轮询（10ms）、心跳灯（1s） |
| `bsp_tmc2209.c`（U2） | 软件 UART（TIM3 位定时，115200）、Trinamic CRC8、寄存器配置与读回校验、地址/引脚自动探测 |
| `bsp_motor.c`（U2） | TIM2 定时中断翻转 STEP、梯形加减速、非阻塞计步、EN/DIR |

## 2. 上电流程

```
HAL_Init → SystemClock_Config → BSP_Clock_Init(兜底 HSE)
MX_GPIO_Init → MX_ADC1_Init → MX_USART1_UART_Init
  ↓
BSP_ADC_Init        ADC 自校准 + VDDA 反算
BSP_UART_Init       按 PC_UART_BAUD 配置 + DMA 接收
[U2] BSP_TMC_Init    TIM3 位定时 + 引脚
[U2] BSP_TMC_Probe   扫地址 0..3，必要时交换 TX/RX 引脚
[U2] BSP_TMC_Configure  写 GCONF/IHOLD_IRUN/TPOWERDOWN/CHOPCONF/PWMCONF/GSTAT
[U2] BSP_Motor_Init  PA0(EN)/PB8(DIR)/PB9(STEP) + TIM2
APP_Init             对射初始化 + 首轮 ADC 快照
PROTO_Init
  ↓
while(1) { PROTO_Run(); APP_Poll(); }
```

## 5. 上板首测清单

**A. 上电与心跳（不接串口）**

1. 上 24V，量 5.1V 与 3.3V 轨正常。
2. 烧 `U1\MDK-ARM\U1\U1.hex`，PC13 应 1Hz 闪（亮 60ms）。不闪 → 检查 BOOT0/H2、复位、晶振。
3. 若怀疑晶振：固件会自动退回 HSI，仍能跑（只是串口精度差一点）。

**B. U1 串口与 ADC**

4. USB-TTL 接 H1（1=RX1 接 TTL 的 TX，3=TX1 接 TTL 的 RX，GND 共地），**115200 8N1**。
5. 发 `A5 5B 00 01 00 01 00 00 89 0C` → 应回 `A5 5B 00 01 00 01 00 01 00 66 ??`（SEQ 回填、DATA=00）。
6. 发 `A5 5B 00 30 00 01 00 00 4D 71`（自检）→ 看 mask：
   - bit0/1/2/3/6 应为 1；
   - `rail_mask` 非 0 说明对应通道贴边（悬空或短路），先查接线；
     **ADC0 直连 3.3V，bit0 恒为 1 属正常，不参与合格判定**。
7. 发 `A5 5B 00 0E 00 01 00 01 01 AA 49`（触发测量）→ 51 字节快照；
   用万用表量各测试点，和报文里的 `mv` 对比，标定分压系数（尤其 ADC2 的 ×2.5）。

**C. 对射**

8. 发 `A5 5B 00 0F 00 01 00 01 00 BB 89`，看 flags bit1/bit2。
9. 遮挡 1 号光路 → 通道1 `blocked` 应变 1、`mv` 升高；松开 → 恢复。
10. 数值贴边（0 或 3.3V 附近）说明光路/接收管方向有问题；用 `0x0021` 调阈值。

**D. U2 与 TMC2209**

11. 烧 `U2.axf`，PC13 心跳正常，H3 串口 PING 正常。
12. 发 `A5 5B 00 20 00 01 00 00 8E B0`（TMC_QUERY）：
    - `alive=1, cfg_ok=1` → 通信与配置都通过；
    - `alive=0` → 先看 PA9 有没有 115200 的 0x05 起始波形；仍不行就把 `app_config.h` 里
      `TMC_TX_PIN`/`TMC_RX_PIN` 对调重烧（固件也会自动换向试一次）；
    - `alive=1, cfg_ok=0` → 某个寄存器读回不一致，看返回的 GCONF/CHOPCONF 值。
13. 电机：先 `0x0022` 设小电流（如 8/4），再 `0x0010` 走 200 步/1000Hz；
    `0x0012` 查 done；确认转向与 DIR 电平一致（低=CW）。
14. 电流逐步加到电机动得稳、不烫（默认 IRUN=16 ≈0.94A，按电机额定调整）。

## 6. 已知风险 / 待硬件确认

| # | 项 | 影响 | 处理 |
|---|---|---|---|
| 1 | 网名 TM_RX / TM_TX 方向（PA9 发送、PA10 接收） | TMC 通信失败 | 固件上电自动换向探测；仍失败可改 `app_config.h` 宏 |
| 2 | TMC 从机地址（MS1/MS2 均上拉 → 3） | 通信失败 | 固件扫描 0..3，不写死 |
| 3 | ADC1（3.6V）直连、ADC6/7 可能接 5V 电平 | 超 3.3V 量程/损坏引脚 | **需硬件确认是否要分压**；固件按 1:1 还原 |
| 4 | 测试点功能表（PDF 表格）与网络对应 | 通道语义错位 | ADC0=3.3V、ADC2=5V 已被电路拓扑验证；ADC1/3/6/7 建议上板用已知电压逐点核对 |
| 5 | 软件 UART 115200 的时序余量 | 偶发读失败 | 可把 `bsp_tmc2209.c` 的 `TMC_BAUD` 降到 9600（U7 参考工程即 9600） |
| 6 | TIM2 中断 40kHz（20kHz 步进时） | CPU 占用 ~6%，脉冲有 µs 级抖动 | 一般可接受；若高速丢步，降低巡航频率或改用硬件 PWM 方案 |
| 7 | 电机额定电流未知 | 力矩不足/过热 | 用 0x0022 在线调，或改 `TMC_DEFAULT_IRUN` |
| 8 | EN(PA0) 不在 CubeMX 配置里 | 重新生成后 PA0 变浮空 | `BSP_Motor_Init()` 每次上电都会手工配置，无需 CubeMX |

## 7. CubeMX 重新生成须知

重新生成工程会覆盖/丢失以下内容（固件已尽量做兜底）：

| 会被覆盖 | 兜底 |
|---|---|
| `SystemClock_Config()`（会变回 HSI） | `BSP_Clock_Init()` 在 USER CODE SysInit 里切回 HSE |
| `usart.c` 的 `BaudRate` | `BSP_UART_Init()` 按 `PC_UART_BAUD` 强制重配 |
| `gpio.c` 的 PA9/PA10/PB8/PB9 电平 | `BSP_TMC_Init()` / `BSP_Motor_Init()` 重新配置 |
| `U1.uvprojx` / `U2.uvprojx` 的 `Application/User/BSP` 分组 | **不会自动恢复**，需手工把那 7~9 个 .c 加回去 |
| 编译宏 `BOARD_U1` / `BOARD_U2` | **不会自动恢复**，需在 C/C++ Define 里补 |

## 8. 只用 U2（U1 不可用）的降级方案

**结论：可以，不需要改代码，直接烧 `U2/MDK-ARM/U2/U2.hex` 即可。**

原因：U2 固件是 U1 功能的**超集**。

| 功能 | U1 | U2 |
|---|---|---|
| PC 串口 115200 | ✅ USART1 PB6/PB7 → H1 | ✅ USART1 PB6/PB7 → H3 |
| 8 路测试点 ADC | ✅ 同一组 ADC0..ADC7 网络 | ✅ 同一组网络（引脚映射不同，报文里的通道号不变） |
| 对射检测 | ✅ ADC4/ADC5 | ✅ 同一组通道 |
| 电机 + TMC2209 | ❌ 没有 EN/STEP/DIR 连线 | ✅ 唯一能驱动电机的一颗 |
| 系统灯 | ✅ PC13 | ✅ PC13 |

U1 没有任何"U2 做不到"的对外功能（它的引脚只有 ADC、USART1、SWD、LED）。

### 切换到 U2 的接线

1. USB-TTL 从 **H1 挪到 H3**，仍 **115200 8N1**。
2. ⚠ **H1 与 H3 的引脚是镜像的**：
   - H1：pin1=U1-RX1，pin3=U1-TX1
   - H3：pin1=U2-TX1，pin3=U2-RX1
   同一根 4P 线插过去，**TX/RX 两根要对着换**（TTL 的 TX 接 H3-pin3，TTL 的 RX 接 H3-pin1）。
3. 协议命令集完全不变（U2 还多了 `0x10/0x11/0x12/0x20/0x22` 电机与 TMC 命令）。
   ADC 报文里仍是逻辑通道 ADC0..ADC7，PC 端不用改。

### 需要注意的差异

| 项 | 说明 |
|---|---|
| 交叉校验 | U1/U2 互检本来就未实现（协议表里那块是 FOC 治具的），只用 U2 不损失已交付功能 |
| 自检结果 | `0x0030` 的 bit4 要求 TMC 通信+配置通过；若只测 ADC/对射而不接电机，自检会回 `0x05`，但从 mask 能看出其余位都正常 |
| 板上还有 U1 | 复位后引脚为高阻/模拟输入，**不会干扰** U2 采 ADC；但如果怀疑 U1 损坏后在乱驱动引脚，把 U1 的 NRST 拉低（或吹掉）最稳妥 |
| 电机 | EN/STEP/DIR 本来就只接 U2，所以"只有 U1 能用"时电机是**做不了**的；反过来才成立 |

### 建议

如果后续要简化 BOM，直接**只贴 U2、U1 位置留空**，固件只维护 `U2` 工程即可；
`U1` 工程保留作为双芯片方案的备份。

新增文件都在 `Core/Src`、`Core/Inc` 下，CubeMX 不会删除。
