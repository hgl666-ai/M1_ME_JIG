# 03 只烧 U2 时怎么自测

> 适用：板上只烧了 `U2/MDK-ARM/U2/U2.hex`（U1 空片或不焊）。
> 自测分三级：**看灯（不用电脑）→ 串口助手发 3 条命令 → 一键脚本全测**。

## 0. 前置条件

| 项 | 要求 |
|---|---|
| 供电 | 板子要按正常方式上电（24V 输入座），**不要**用 USB-TTL 的 3.3V 反灌 |
| 串口 | 接 **H3**（不是 H1！只烧了 U2，H1 那头是 U1，不会有任何应答） |
| 接线 | TTL 的 **TX → H3-pin3（U2-RX1）**，TTL 的 **RX → H3-pin1（U2-TX1）**，**GND 必须共地** |
| GND | ⚠ H1/H3 都**没有 GND 针**：从 24V 输入座或测试点排针的 GND 取 |
| 电平 | 3.3V TTL（CH340/CP2102 的 3.3V 档；RS232 电平会打坏引脚） |
| 波特率 | **115200**，8N1，无流控 |

> H3 引脚：1=U2-TX1，2=U2-SWD，3=U2-RX1，4=U2-SCLK。
> 和 H1 是**镜像**的（H1 的 pin1 是 RX，H3 的 pin1 是 TX），同一根线插过去 TX/RX 要对调。

## 1. 第一级：只看灯（完全不接电脑）

上电后 **PC13 应 1Hz 闪**（亮 60ms、灭 940ms）。

- 闪 → 固件已在跑（时钟、GPIO、主循环都正常），可以进第二级。
- 不闪 → 固件没跑起来：查 BOOT0（H2 跳线应为 0）、NRST、是否烧到 0x08000000、电源。
  （晶振不起振不会导致不闪——固件会自动退回内部 HSI。）

## 2. 第二级：串口助手发 3 条命令

串口助手设置：**HEX 发送 + HEX 显示**，115200 8N1。

| 步骤 | 发送（HEX） | 预期应答 |
|---|---|---|
| ① PING | `A5 5B 00 01 00 01 00 00 89 0C` | `A5 5B 00 01 00 01 00 01 00 95 88`（11 字节） |
| ② 版本 | `A5 5B 00 02 00 01 00 00 89 48` | `A5 5B 00 02 00 01 00 04 00 01 00 00 4A 66`（14 字节，v1.0.0） |
| ③ 自检 | `A5 5B 00 30 00 01 00 00 4D 71` | 16 字节，DATA[0]=`00`，DATA[1] 是自检位图 |

③ 的应答结构（共 16 字节）：`A5 5B | 00 30 | <SEQ> | 00 06 | 状态 mask VDDA_H VDDA_L 贴边 CRC错 | CRC16`。
判定：

- `状态 = 00` → 全部通过（含 TMC 通信+配置）。
- `状态 = 05` → 有位没过，看 `mask`：
  `bit0` 8路ADC、`bit1` 对射1、`bit2` 对射2、`bit3` VDDA、`bit4` TMC、`bit5` 电机空闲、`bit6` 串口无溢出。
- **没接电机时 bit4=0 是正常的**，不算故障。

## 3. 第三级：一键脚本（推荐）

```bat
:: 先关掉串口助手（COM 口不能被两个程序同时占用）
D:\Develop\python\python.exe tools\u2_selftest.py --port COM4
:: 想顺便验证电机转动：
D:\Develop\python\python.exe tools\u2_selftest.py --port COM4 --motor
```

脚本会依次测 PING → 版本 → 自检位图 → 8 路 ADC（逐通道打印 raw/mV/贴边）→
对射两路（连续采样，可人工遮挡看翻转）→ TMC 状态；加 `--motor` 再转 200 步并查到位。

依赖 pyserial（`pip install pyserial`）。

## 4. 其他常用命令（手动验证用）

| 用途 | 发送（HEX） |
|---|---|
| 触发一次 8 路 ADC | `A5 5B 00 0E 00 01 00 01 01 AA 49` |
| 读对射状态 | `A5 5B 00 0F 00 01 00 01 00 BB 89` |
| 查 TMC2209 | `A5 5B 00 20 00 01 00 00 8E B0` |
| 设对射阈值（ch0，2000/1700mV） | `A5 5B 00 21 00 01 00 05 00 07 D0 06 A4 F4 39` |
| 电机 CW 200 步 1000Hz | `A5 5B 00 10 00 01 00 07 00 00 00 00 C8 03 E8 C3 2F` |
| 电机状态 | `A5 5B 00 12 00 01 00 00 4A 89` |
| 电机停 | `A5 5B 00 11 00 01 00 00 4A CD` |

ADC/对射/TMC 应答的字段定义见 [`01_PC协议.md`](01_PC协议.md) 第 4 节。

## 5. 现象 → 原因 对照表

| 现象 | 最可能的原因 | 处理 |
|---|---|---|
| 灯不闪 | 没跑起来 | 查 BOOT0(H2)、复位、烧录起始地址 0x08000000 |
| 灯闪，PING 无任何返回 | 接在 **H1** 上（U1 空片） | 换到 **H3** |
| 灯闪，PING 无返回（确认在 H3） | TX/RX 没交叉、没共地、TTL 电平不对 | 对调 TX/RX；接 GND；用 3.3V 档 |
| 有返回但全是乱码/CRC 错 | 波特率不是 115200，或 GND 接触不良 | 核对波特率；短接 GND 再试 |
| PING 正常，自检 bit0=0 | ADC 采样异常 | 固件问题，重烧；查 3.3V 供电 |
| 自检 bit1/2=0 | 对射两路采样失败 | 查 PT334 供电/焊接 |
| 自检 bit3=0 | VDDA 不在 3.0~3.6V | 量 3.3V 轨 |
| 自检 bit4=0 | TMC 通信/配置失败 | 看 `0x0020` 的 alive/cfg；没接电机属正常 |
| 自检 bit6=0 | 串口 FIFO 溢出 | 主循环被长耗时命令占住，降低查询频率 |
| ADC 某通道“贴边” | 该通道 0V 或 3.3V（悬空/短地/超量程） | 量该测试点电压 |
| TMC alive=0 | PA9/PA10 方向反、TMC 没供电、地址不对 | 固件会自动换向；仍失败看 PA9 有无 115200 的 0x05 波形 |
| TMC alive=1 但 cfg_ok=0 | 寄存器读回不一致 | 看返回的 GCONF/CHOPCONF 是否像被改写 |
| 电机不转 | 电流太小 / EN 未使能 / 未配置 | 先 `0x0022` 设 12/6，再 `0x0010`；听是否有保持力矩 |

## 6. 如果要切回 460800

协议表里原写的是 460800。如果 PC 端已经按协议表实现，把
`U1/Core/Inc/app_config.h` 和 `U2/Core/Inc/app_config.h`（**两份必须一致**）里的
`PC_UART_BAUD` 改成 `460800u`，两颗分别重新编译烧录，串口助手/自测脚本的波特率也跟着改。

> 为什么默认选 115200：M1 最长帧只有 61 字节（115200 下约 5.3ms 发完），带宽绰绰有余；
> 460800 对杜邦线、接触电阻和电平质量更敏感，产线治具用 115200 更稳，也和现有程序统一。
> 时钟误差不是障碍——HSE 8MHz 下 115200 的 BRR 误差约 0.08%，460800 也一样。
